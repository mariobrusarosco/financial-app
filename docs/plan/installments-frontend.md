# Installments (Parcelamento) Frontend Implementation Plan

## Overview
This plan outlines the implementation of the **Installments** feature as a standalone domain. Users will manage installment plans separately from single transactions, providing a dedicated workflow for tracking large purchases split over time.

# Phase 1: Data Layer & API Integration

## Goal
Establish the foundational TypeScript models and API client for the `InstallmentPlan` domain, ensuring separation from the core `Transaction` write operations.

## Tasks

### Task 1 - Define Types [x]
#### Task 1.1 - Create `src/domains/installments/types/types-and-interfaces.ts` [x]
#### Task 1.2 - Define `I_InstallmentPlan` (id, description, total_amount, total_installments, start_date, status, vendor_id, category_id) [x]
#### Task 1.3 - Define `I_Installment` (child record: number, amount, due_date, status) [x]

### Task 2 - API Client & Keys [x]
#### Task 2.1 - Create `src/domains/installments/api/installments.api.ts` (CRUD for Plans) [x]
#### Task 2.2 - Create `src/domains/installments/api/keys.ts` [x]

### Task 3 - React Query Hooks [x]
#### Task 3.1 - Create `useInstallmentPlans` (List) [x]
#### Task 3.2 - Create `useInstallmentPlan` (Detail) [x]
#### Task 3.3 - Create `useCreateInstallmentPlan` (Mutation) [x]
#### Task 3.4 - Create `useUpdateInstallmentPlan` & `useDeleteInstallmentPlan` [x]

## Dependencies
- Backend Phase 1 (Models & Migrations)

## Expected Result
- The frontend can independently fetch and manage Installment Plans without relying on the Transaction API.
